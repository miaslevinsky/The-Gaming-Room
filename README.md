# CS 230 – Software Design Document

## Project Overview

The Gaming Room was the client for this project. They wanted to expand their existing Android game, *Draw It or Lose It*, into a web-based application that could work across multiple platforms. The game allows teams to guess images as they are displayed. The client needed a design that would support multiple users, maintain game and team information, prevent duplicate names, and provide a secure and reliable experience across different devices.

## What did you do particularly well in developing this documentation?

I think I did a good job comparing different operating platforms and explaining which options would work best for The Gaming Room. I was able to look at the advantages and disadvantages of Windows, Linux, macOS, and mobile platforms while considering performance, security, and cost. I also feel that I did well organizing the document so the client could understand my recommendations and why I chose them.

## What about the process of working through a design document did you find helpful when developing the code?

Working through the design document helped me better understand the requirements before starting the actual development process. It allowed me to break down the application into smaller parts and think about how everything would work together. Having a clear plan made it easier to understand how the classes, design patterns, and different components of the application should interact.

## If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

If I could revise one part of my design document, I would focus on the security recommendations. Although I covered important features like authentication, authorization, and encryption, I think I could have gone into more detail about how these features would actually be implemented. I would also include more examples of potential security threats and explain how the application could protect user information.

## How did you interpret the user's needs and implement them into your software design? Why is it important to consider the user's needs when designing?

I approached the client's needs by reviewing their requirements and thinking about how the application would be used across different platforms. Since The Gaming Room wanted multiple users to access the game, I focused on creating a design that would be scalable, secure, and easy to maintain. I also considered how the system would manage games, teams, and players without allowing duplicate names. Understanding user needs is important because it helps developers create software that works the way the client expects and provides a better experience for everyone using it.

## How did you approach designing software? What techniques or strategies would you use in the future?

My approach was to first understand the client's requirements and then compare different technologies to determine which would work best. I looked at operating systems, memory management, storage, security, and overall application performance before making my recommendations. In the future, I would continue using design documents, UML diagrams, and research to plan applications before writing code. I would also focus on testing and reviewing requirements throughout development to make sure the final application meets the client's expectations.
